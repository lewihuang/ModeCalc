# 2026-10-26：macOS 独立 App 与双平台构建

## 实现

- Windows 沿用 PyInstaller；Mac 新增 py2app standalone 构建、图标转换、资源与许可证收集、架构和外部依赖检查、签名及 ZIP / SHA256 输出。
- 新增 Universal 2 构建脚本，合并两种架构的 RtMidi 扩展；保留 M 专用包并移除其中多余架构，ZIP 约为 26 MB / 18 MB。
- 新增共享版本元数据，Windows 构建自动同步版本资源。
- Mac 使用 Cocoa / WKWebView 与 CoreMIDI。资源通过回环静态服务加载，网络声明仅允许本地网络；前端明确区分桌面 bridge 与浏览器 WebSocket 模式。
- 将原生 MIDI 初始化延后到前端桥接握手，避免 Cocoa 尚未就绪时创建 MIDI 客户端；后台命令、状态发布与退出收尾有明确生命周期。
- 端口按约一秒刷新，支持部分打开失败、拔插恢复、切换时丢弃旧回调。按来源和通道保存音符、延音状态，避免多设备同音及踏板互相干扰。
- Mac 设置迁移到 Application Support，日志使用 Library/Logs 并轮转；保留环境变量原语义及旧设置文件。
- 修复 WKWebView 在样式初始化后重建字体对象导致的假就绪：显式加载 CSS 字体、在 bridge 就绪后重新检查，并保留不可见预加载字形。
- 增加窗口缩放适配和 Mac 设置快捷键。对 MIDI 异步响应加序号，防止旧响应覆盖新状态。
- CI 配置 Windows exe 构建、Mac 两架构构建和真实 CoreMIDI / WKWebView 冒烟；另有手动触发的 Developer ID 公证工作流。

## 已完成的本机验证

- Apple Silicon / macOS 26.4.1。
- 137 项 Python 测试通过，包含原有 124 项回归。
- 独立 `.app` 的真实 CoreMIDI 虚拟输入到和弦、谱表、键盘及指板显示通过；重复启动验证通过。
- 每包 68 个原生文件的架构通过递归验证：Universal 2 全部包含 arm64 和 x86_64，M 专用包全部仅包含 arm64。通用包两个架构分支的实际 MIDI 与界面测试均通过，x86_64 分支使用 Rosetta；未发现开发机 Python / 动态库绝对路径依赖，原生依赖的最高最低系统要求为 macOS 11。
- 中文自定义音阶新增、编辑、退出重启后的恢复，以及 `Cmd+,`、`Cmd+Q`、关闭窗口退出通过实际界面操作验证。
- ZIP 解压至中文、空格路径、只读资源目录运行检查通过，运行后签名仍完整。

## 发行边界

当前产物为本地 ad-hoc 签名测试包。Developer ID 加固签名、公证、Intel / macOS 14 真机、物理 USB MIDI 与 Windows exe 仍需对应环境验收；GitHub CI 配置尚未在远端执行。正式包应使用当前安全补丁版本的 Python 3.12 framework 构建。

操作方法见 [macOS 构建与验证](../MACOS_BUILD.md)。本次未修改和弦、调式算法和音阶库数据模型，也未提交或发布远端版本。
